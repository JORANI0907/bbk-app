# 계약서 압축 + 회사규정 연동 실행 계획 (3·4·5단계)

> 작성 2026-11-27. 1단계(방향·조항 분류)와 2단계(규정 단일 출처 정비)는 완료. 규칙별 주인 문서는 `docs/regulations/rule-registry.md`.
> 원칙: 계약서는 돈·기간·해지·배상 한도만. 절차는 CP-01, 숫자는 주인 문서. 규정은 코드+판으로 가리키고 조 번호는 적지 않는다.

## 0. 현재 구조 (바꾸지 않고 재사용하는 것)

| 구성 | 현재 | 이번에 하는 일 |
|---|---|---|

## 1. 3단계 — 컴팩트 계약서 양식 1종

### 1-1. 양식 설계

- 이름: `정기 서비스 계약서 v5 (컴팩트)` 1종. 딥/엔드 구분과 결제 방식은 「계약 내용」 표 값으로만 다르게.
- 본문 10조 (1단계에서 확정): 계약의 내용 / 기간·연장 / 대금·결제 / 대금 조정 / 일정 / 중도 해지·정산 / 품질 보증 / 책임·면책 / 준거 문서 / 효력.
- 결제 블록 3종을 양식 3개로 나누지 않는다. 3조는 "「계약 내용」에 정한 방식과 기일"로 쓰고, 선납형 한 문장("기간 선납 계약은 정한 기일까지 계약금이 납부되지 않으면 효력이 생기지 않는다")만 조건부로 둔다. 방식별 설명은 CP-05 제6조 표가 주인.
- 별지 1 「계약 내용」: 서비스 유형, 기간, 청소 범위, 방문 주기·요일·시간, 회당 금액(공급·VAT), 결제 방식·기일, 사업장·출입 방법 한 줄, (엔드케어) 방문 옵션 주N회.
- 별지 2 「공동계약 지점 목록」: 공동계약일 때만.
- 서명 전 「중요 내용 확인」 4개: 자동 연장(2조), 중도 해지 정산(6조), 배상 한도(8조), 준거 문서 열람(9조).

### 1-2. 엔드케어 전용 내용 처리

현행 엔드케어 v6 에만 있는 것: 제4조 방문 옵션 표(주1~7회), 부속 합의 4조(표준범위 별지 / 품질관리 매뉴얼 / 차등·정산 단가 별표 / 비밀유지 존속).
- 방문 옵션 → 「계약 내용」 "방문 주기" 칸에 "주3회(월·수·금) 21:00" 식으로 기재. 옵션 표는 안내 자료로 빼고 계약서에서 삭제.
- 표준범위 별지 → 「계약 내용」 청소 범위 칸 (이미 같은 역할).
- 품질관리 매뉴얼·3개월 3회 해지 → CP-01 제19·20조로 이동 완료.
- 차등 단가 별표 → 6조에 `{{규정:CP-03:9}}` 로 CP-03 제9조 조문을 삽입(아래 변수).
- 비밀유지 존속 → CP-01 제24조 ③.

### 1-3. 규정 변수 3종 (양식에 쓰는 새 변수)

| 변수 | 치환 결과 | 출처 |
|---|---|---|
| `{{규정:CP-03:9}}` | CP-03 발행본 제9조 전체(제목+항+호)를 `<blockquote>` 로 삽입 | `regulation_versions.html_body` 를 `lib/regulations/articles.ts` 의 조 분해 함수로 잘라냄 |
| `{{규정버전:CP-03}}` | "CP-03 예약 취소·변경 및 환불 정책 (제1판, 2026-12-01 시행)" | `regulations` + 현재 발행본 |
| `{{준거문서표}}` | 9조의 표: 문서 / 판·시행일 / 열람 주소 `app.bbkorea.co.kr/policy/CP-01/v/1` | 양식 `var_config.regulation_refs` 에 적힌 코드 목록 |

- 계약 생성 시점의 **발행본**으로 치환하고, 그 version id 를 `contract_snapshot.regulation_refs[]` 에 기록한다. 발행본이 없으면 생성을 막는다(조용히 빈칸으로 두지 않음).
- 미리보기(`/api/admin/contracts/preview`)에서는 발행본이 없을 때 초안으로 대신 치환하고 "초안 기준" 띠를 보여준다. 실제 생성은 발행본만.

### 1-4. 산출물·검증

- 스크립트 `scripts/contract-template-v5-compact.mjs` 로 양식 1건 insert (기존 5종은 `is_active=false` 로만 내리고 삭제하지 않음 — 과거 계약 스냅샷은 영향 없음).
- 샘플 계약 초안 1건(팝성형외과의원 정기딥케어 2027-05~)을 만들어 미리보기·PDF 로 2장+별지 분량 확인.
- 글자 수 목표: 본문 2,500자 안쪽. 현행 12,700자.

## 3. 5단계 — 적용 순서

1. 대표 검토: CP-01·02·03·04·05 초안 읽고 수정 지시 → 반영.
2. 발행: 시행일 확정(제안 2026-12-01) 후 관리자 화면에서 CP-01·03·05 발행, CP-02·04 는 같은 날 또는 검토 후. 발행 조건: 조 번호 빠짐·중복 검사 통과(이미 통과).
3. 4단계 배포 → 관리자에서 v5 양식으로 초안 1건 만들어 미리보기·서명 화면·PDF 별첨 확인.
4. v5 양식 활성화(`node scripts/contract-template-v5-compact.mjs --apply --activate`), 기존 5종 비활성.
5. 신규 계약부터 v5 양식 사용. 기존 5종 양식 비활성. 진행 중(서명 대기) 계약은 그대로 두고, 기존 완료 계약은 만기 재계약 때 전환.
6. (취소) 옛 약관 페이지는 손대지 않음.
7. 한 달 뒤: 레지스트리 기준으로 숫자 중복 검사 스크립트 재실행(2단계에서 쓴 grep 패턴을 `scripts/regulations-check-duplicates.mjs` 로 고정).

## 4. 위험과 대응

| 위험 | 대응 |

| 약관 참조가 "설명 의무" 미이행으로 무효 주장 | 서명 전 확인 체크 4개 + 준거 문서 열람 체크 + 시각·IP 기록. 중도 해지 정산식·배상 한도·자동 연장은 본문에 직접 기재 |
